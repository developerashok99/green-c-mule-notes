In today's session we will first see Scatter-Gather. Scatter-Gather is also a component for us; we will discuss how to use it and in which situations. Then we will move on to the next component, the Async scope.

First, Scatter-Gather. As soon as we see the name: we scatter something and then gather it again. First we scatter, then we gather. We will remember it as soon as we see the name.

[drawing: an API calling Amazon, Flipkart and TATA Cliq REST services one after another — 250 + 350 + 400 ms]

The price comparison website has tied up with Amazon, Flipkart and Tata Cliq, and these three have exposed their APIs; let's consider them REST APIs. So Amazon has an API, Flipkart has an API, and Tata Cliq has an API.

The comparison website is developing an API in the backend. When they get a request from the front end — for example, compare prices for an iPhone — the request comes in. Immediately it communicates with the Amazon REST API. What do we use for a REST API? The HTTP Request connector. We send the request to Amazon and get the response, with all the price details from Amazon. Say it took around 250 milliseconds. Then I send it to Flipkart, and Flipkart responds in 350 milliseconds. Then Tata Cliq responds in 400 milliseconds. And it is not just these three HTTP requests — there will be other processing too.

[drawing: sequential total = 250 + 350 + 400 + 200 = 1200 ms]

— No dependency.

— Yes.

[drawing: Scatter-Gather — the same three calls sent in parallel routes and gathered at the end]

Then tell me what happens if I send to the three sites at the same time. First we scatter the request into three routes. What does scatter mean? In the first route the request goes to Amazon and gets the response; in the second route it goes to Flipkart; in the third route it goes to Tata Cliq. We execute the three routes at the same time. At 250, Amazon is finished: the response has come. Then what? It comes to the gather point and waits for the others. At 350 Flipkart arrives, at 400 Tata Cliq. So how much time did it take for all three? 400 milliseconds. Plus the other components, 200. 400 plus 200 is 600 milliseconds.

[drawing: with Scatter-Gather the time is the slowest route + 200 = 400 + 200 = 600 ms]

So what happened here? Since there is no dependency and there is scope for parallel processing, I can use Scatter-Gather at such times. The Scatter-Gather component gets the request and sends it to all three routes — route 1, route 2, route 3 — at the same time. Amazon, Flipkart and Tata respond; we gather the responses and pass them to the next component. Route 1 takes about 250 ms and waits at the gather; route 2 at 350 ms waits; route 3 is 400 ms. That is how Scatter-Gather processes a request in multiple routes simultaneously.

What is the time taken by the whole Scatter-Gather? The maximum time taken by any one route. Among the three routes, the maximum is 400 milliseconds — route 3, Tata Cliq. So the Scatter-Gather takes 400 milliseconds; the other components about 200. 400 plus 200 is 600, as we discussed. What is the advantage? Time saving.

Next scenario: the response from Amazon must be the input to Flipkart. Can Scatter-Gather be used then? It can't. Please note that. Or the response from Flipkart must go to Tata Cliq, or Flipkart must be called only after the Amazon request is done — when such a dependency is compulsory, you can't use the Scatter-Gather component. Whenever there is a situation for parallel processing, where the calls are independent of each other with no relationship between them, you use Scatter-Gather, process in parallel, and automatically reduce the total time of the API. The sequential API is not a wrong process; if we want to increase performance, we use Scatter-Gather to save time.

How many routes should a Scatter-Gather have? At least two. Why? If there is only one, what is the use? No use — we can use normal components. There should be at least two routes. I'm not sure about the maximum; in my experience I use up to four or five. I haven't observed any restriction or seen one mentioned anywhere; you can try and see.

And we also gather here. What do we gather? The collection of the first route's response, the second route's response and the third route's response, and that is passed on. When the request goes into the Scatter-Gather, the same request goes to the first, second and third route: for all three, the payload is the same, the attributes are the same, the variables are the same.

— These are in multiple APIs?

No, this is all within the same API — our API. In the first approach, one API with three HTTP connectors one after another takes 1200 milliseconds. Instead, we drag-drop a Scatter-Gather, and in the first route we have one HTTP connector, in the second route one, and in the third route one — still one API.
