In the previous sessions we saw the CloudHub deployment model and then on-premises. Today we look at the hybrid model.

First, recall the runtime plane and control plane. How did on-premises work? We deployed the application directly into the runtime and checked the logs there; there was nothing like a Runtime Manager. In real time it's almost like that. Another option is that Anypoint Platform itself is set up on our servers by the MuleSoft team, but most of the time what I see on-premises is: log in to the Mule runtime box directly to check logs, and start, stop and restart there.

Now the hybrid model: a combination of on-premises plus MuleSoft-provided services. Which part is on-premises and which is MuleSoft's? The services provided by MuleSoft — the control plane — come from MuleSoft. The runtime — where we deploy applications — is the client's. The Mule runtime sits on the client's server. For example, ICICI Bank uses the MuleSoft platform for integration: the server with the Mule runtime is in the ICICI data centre. Then Anypoint Platform — Runtime Manager, API Manager and so on — we use in the cloud provided by MuleSoft.

You may ask: this is on-premises and that's in MuleSoft's cloud — how do the two connect and communicate? There are a few steps.

[drawing: Hybrid — runtime on-premises (client) ↔ control plane in the cloud (MuleSoft), connected by two-way SSL through the runtime agent: ① Register the server in RTM ② Install the runtime agent in the server ③ Deploy the app.]

We have Mule runtimes on our servers. We register them in the control plane — Anypoint Platform activities are the control plane; where the application runs is the runtime plane.

1. Register the server. When we click register, we get a small command; we take it to that server and run it.
2. Install the runtime agent in the server. Running that command installs the runtime agent into this Mule runtime. It establishes a connection between our runtime server and the control plane for communication.

If that communication isn't secure, it causes trouble. So it uses two-way SSL. Think of WhatsApp: when a message goes to your friend it's encrypted, and decrypted on the other side — the communication is secure. Similarly here, communication happens in the most secure way, two-way SSL, via the runtime agent.

3. Then you can deploy applications.

That's the hybrid model. Applications are deployed here; all the logs are here; all the connectors and configurations are here; all the code is here. Only the control is through the control plane — Runtime Manager. From Runtime Manager we can start the application, stop it, restart the server — all from there. On plain on-premises, we'd have to log in directly and do everything there; we couldn't do it from MuleSoft's control plane. Is that clear to everyone? Yes, sir.
