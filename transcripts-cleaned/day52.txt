[slide: What is Object Store? — a Mule component for simple key-value storage; mainly for synchronization info such as watermarks and temporary data such as access tokens; the Cache module uses an object store; available as transient or persistent storage]

In today's session we will see the Object Store: what it is and, in detail, how we can use it, and then a demo as well. Object store is a generic concept, not a MuleSoft-specific one; we need to know how to implement it in MuleSoft.

What is an object store basically? We can use it for storage purposes. "Object Store is a Mule component that allows for simple key-value storage." For example, I want to save an employee's address: the entire address is saved as the value under a key — address lines 1 to 5 and so on, in the form of key–value. The Object Store component helps store values like that.

Why is it necessary? Key–value storage — but there is a database; why do we need an object store? We could save it there and bring it back. The problem is a database operation is a costly operation. It's valuable for permanent information, but for temporary information, instead of costly operations like the database, it's good to have a storage option. So the industry introduced the concept of an object store.

What can temporary information be? Generally, the concept of watermarks — how to store those watermarks. And access tokens. For example, with policies we got a token; say it has a validity of one hour. I have to save that one-hour-valid token and use it. How? Store it, and retrieve it for reuse.
